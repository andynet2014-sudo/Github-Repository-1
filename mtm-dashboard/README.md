# 리스크 대시보드 수집기 (MtM Dashboard)

`260731_리스크관리대시보드_v2.4.5` 구글시트의 리스크 엔진을 스프레드시트에서 파이썬으로
옮긴 것. **지표 정의는 하나도 바꾸지 않았다.** 계산이 일어나는 위치만 바뀌었다.

목적은 하나 — **매일 입력을 0으로 만드는 것.**

```
국장 총평가 = Σ(수량 × 시세) + 예수금
              └ 거래한 날만   └ 자동   └ 거래한 날만
```

## 빠른 시작

씨앗 추출(구글시트 → CSV)은 이미 한 번 끝났다. 이후로는 이 폴더 안에서 이것만 돌리면 된다.

```bash
cd mtm-dashboard
python3 collect.py                        # 매일 (또는 cron)
```

`verify_against_sheet.py`/`--backfill` 는 구글시트를 다운받은
`.xlsx` 파일이 있어야 도는 일회성 스크립트다. 그 파일은 저장소에 안 남겨뒀다 —
다시 필요하면 구글 드라이브의 원본을 다시 내려받아 넘기면 된다.

## 파일 역할

**사람이 만지는 파일은 `positions.csv` 하나다.** 구조를 Q(수량) × P(가격)으로 통일했다 —
주식도, 예수금도, 신용잔고도 전부 이 파일의 행이다.

| 파일 | 내용 | 갱신 시점 |
|---|---|---|
| `data/positions.csv` | 종목(수량·평단·손절가·섹터) + 예수금(`sector=현금`) + 신용잔고(`sector=신용`) | **거래·입출금·신용변동 있는 날만** |
| `data/common.csv` | 회사대출·담보비율·연봉·원금·누적비용 | 바뀌었을 때만 |
| `data/rules.csv` | 룰북 임계값 | 기준을 바꿀 때만 |

나머지는 스크립트가 쓴다 — `prices.csv`(시세 캐시), `daily.csv`(계좌 합계 이력),
`positions_history.csv`(종목별 이력).

`accounts.csv` 는 삭제됐다. 신용잔고는 `CREDIT_국장` 행으로 `positions.csv` 안에 들어갔다
(미장·ISA 는 애초에 신용거래가 불가능해 행 자체가 없다).

## 명령어

| 옵션 | 용도 |
|---|---|
| (없음) | 시세 조회 → 계산 → 기록 → `positions.csv` 현재가 갱신 → `positions_history.csv` 에 그날 종목별 스냅샷 적재 |
| `--dry` | 계산만, 저장 안 함 (현재가도 안 씀) |
| `--no-fetch` | 시세 조회 없이 캐시로 재계산 |
| `--date 2026-08-12` | 특정 날짜로 기록 |
| `--backfill <xlsx>` | `01_일별로그` 과거 이력 복원 (구글시트 다운로드본 필요) |

같은 날 여러 번 돌려도 행이 늘지 않고 덮어쓴다.
시세 조회가 실패하면 캐시로 대체하고, **어떤 종목이 왜 실패했는지 출력한다.**
매 실행마다 `positions.csv` 의 `current_price_krw` 열도 오늘 시세로 갱신된다
(`qty`·`avg_price_krw`·`stop_price_krw` 등 사람이 입력한 칸은 건드리지 않는다).

## 검증

`verify_against_sheet.py` 가 계산값을 스프레드시트의 `③ 포지션 ④ 리스크 엔진` 셀과 직접 대조한다.
구글시트를 다시 다운받아 파일 경로를 넘기면 언제든 재검증할 수 있다.

```bash
python3 verify_against_sheet.py <다운받은 xlsx 경로>
```

26개 지표가 스프레드시트 값과 정확히 일치했다 — 정의를 그대로 옮겼다는 근거다.

## 실질 누적 순손익

`principal_total`(누적 순투입 원금) · `cum_course_fees`(강의·구독비) · `cum_interest`(참고용,
차감 안 함) · 계좌별 `principal_국장`/`principal_미장`/`principal_ISA` 이 다섯 값은 이제
**`data/cashflow.csv` 에서 매 실행마다 자동으로 합산**된다 (`load_cashflow_totals()`) —
거래원장에 행을 추가하면 다음 `collect.py` 실행부터 곧바로 반영되고, `common.csv` 를
따로 손댈 필요가 없다. `cum_tax_est`(해외주식 예상세액)만 여전히 `common.csv` 에 손으로
넣는다(실현손익 기반 추정이라 원장에서 자동 계산되지 않음). `cashflow.csv` 가 없거나
비어 있으면 `common.csv` 의 값을 그대로 쓴다(안전장치).

표면 손익(계좌 순자산 − 원금)에서 강의비·세금만 뺀 게 실질 순손익이다
(v2.4.5 `03_Cashflow`(구 07_CF_원금, 구 09) Ⅴ 와 같은 정의).

## 웹 대시보드 (MtM Dashboard)

리스크 신호등·계좌·포트폴리오·실질 순손익은 이 저장소 데이터로, 매매일지·뷰트래커·
생각노트는 구글시트로 만든 통합 스냅샷 페이지가 따로 있다. 정적 스냅샷이라 자동
갱신되지 않는다 — 최신 내용으로 다시 보고 싶으면 요청하면 된다. 저장소에는 생성
스크립트를 아직 안 넣었다 (요청 시 만들 예정).

월간결산은 daily.csv 에 순자산(`equity`)이 찍힌 날이 아직 며칠 안 돼서 완전하게는
못 낸다 — 데이터가 쌓이는 대로 자동으로 채워진다.

## 알아둘 것

**손절가가 평단과 같다.** 9종목 중 8종목의 `stop_price_krw` 가 평단과 완전히 동일하다
(예: SK하이닉스 1887803.429). 지금 R04·R05 가 재는 건 "손절선 하회"가 아니라 **"본전 밑"** 이다.
`data/positions.csv` 에서 고치면 바로 반영된다. 실제 손절가를 넣기 전까지 이 두 신호는
의미가 약하다.

**R07 은 시트에 기준값이 비어 있다.** 그래서 스프레드시트에서는 레버ETF가 순자산의 67%인데도
🟢 준수로 표시된다. 여기서는 잠정 기준 50%를 적용해 🔴 위반으로 잡고, 출력에 `※ 기준값 미설정`
을 붙여 둔다. `data/rules.csv` 의 `threshold` 를 채우면 잠정값 대신 그 값을 쓴다.

**SOXL 은 3배 레버리지로 잡혀 있다.** (8/12 아마존 전량 매도 → SOXL 254주 매수 반영,
평단 192,157원 / 손절 180,000원 확정) `lev=3` 을 직접 넣었다 — 안 넣으면 실질 Exposure 가
3배 축소되어 레버리지가 실제보다 낮게 나온다. `positions.csv` 의 `lev` 를 확인할 것.
섹터도 반도체 ETF라 반도체/HW 로 분류했다.

**예수금은 이제 `positions.csv` 안에 있다.** `sector=현금`, `ticker=CASH_국장` 처럼
계좌별로 행이 하나씩 있고, `qty=1` 고정 · `avg_price_krw`/`current_price_krw` 칸에
잔액을 그대로 적는다 (시세 조회 안 함, 사람이 적은 값을 그대로 씀). `compute()` 는 이
행들을 주식 계산(명목·Exposure·섹터·손절)에서 전부 빼고 계좌별 현금으로만 합산한다.
잔액이 바뀌면 이 행의 `avg_price_krw`/`current_price_krw` 를 고치면 된다.
**신용잔고도 같은 방식이다** — `sector=신용`, `ticker=CREDIT_국장` 행 하나로 들어간다.

**2026-08-12 예수금은 역산값이다.** 사용자가 그날 실제 계좌 순자산(국장/미장/ISA)을
불러줬는데, 이 저장소엔 실시간 시세가 없어(프록시가 야후·네이버 접근을 막음)
`positions.csv` 의 캐시된 가격으로 명목평가를 구한 뒤 `예수금 = 순자산 − 명목평가 + 신용`
으로 역산해 채웠다. 국장이 2,173,938 → 73,191,440원으로 크게 뛰었는데, 이 중 상당 부분은
실제 입출금이 아니라 **캐시된 가격이 실제 시세보다 낮아서 생긴 차이일 수 있다** — 다음에
실시세로 다시 돌리면 이 갭이 다시 예수금 쪽으로 흡수되며 조정된다. 실제 시세를 알고 있다면
`current_price_krw` 를 먼저 갱신한 뒤 예수금을 다시 계산하는 게 더 정확하다.

**감정 태그는 `--emotion` 으로 남긴다.** `python3 collect.py --emotion 탐욕` 처럼 실행하면
`daily.csv` 의 그날 행에 `emotion` 열로 기록된다. 안 주면 기존 값을 그대로 이월한다.

**과거 이력은 구간을 나눠 담았다.**

| 구간 | 일수 | 쓸 수 있는 것 |
|---|---|---|
| 2026-06-01 ~ 07-29 | 43일 | 국장 총평가·순자산만 |
| 2026-07-30 ~ 08-04 | 3일 | 미장·ISA는 있으나 국장 순자산 없음 |
| 2026-08-10 ~ | 2일 | 전체 순자산·레버리지·청산여력 |

`equity`(전체 순자산)는 세 계좌가 모두 있는 행에만 채웠다. 국장 값만 넣어 "전체 순자산"으로
그리면 6~7월 추이가 실제보다 낮게 나온다. 국장 순자산 흐름(809,140,626 → 271,010,915, 45일)은
연속으로 잡히므로 차트용으로는 충분하다.

## 시세 출처

- 국내: 네이버 금융 → 실패 시 야후(`.KS` → `.KQ`)
- 해외: 야후 + `USDKRW=X` 환율로 원화 환산

`0193T0`(SK하이닉스X2), `0193W0`(삼성전자X2) 같은 ETN은 제공처에 따라 조회가 안 될 수 있다.
그 경우 캐시 값이 쓰이고 경고가 뜨므로, 뜨면 `data/prices.csv` 를 직접 채워 넣으면 된다.

## 매크로 지표

`collect.py` 실행마다 야후 파이낸스에서 매크로 지표 4개를 함께 조회해 `data/macro.csv`
에 하루 한 줄씩 쌓는다. 실패하면(네트워크 차단 등) 전날 값을 그대로 이월한다.

| 지표 | 야후 티커 | 비고 |
|---|---|---|
| 미국채 10y 금리 | `^TNX` | 야후 값이 %의 10배라 `collect.py`에서 10으로 나눠 저장 |
| WTI 선물 | `CL=F` | 달러 표시 그대로 저장 |
| KOSPI | `^KS11` | |
| KOSDAQ | `^KQ11` | |
