  단절). 다행히 MtM 작업은 별도 브랜치(`claude/google-drive-connector-folders-lu7bxq`)에

  - **`MtM-Dashboard`**(이 저장소, 원래 `260731-` → `Github-Repository-1` → `MtM-Dashboard`로
    두 번 개명됨) — 트레이딩 리스크 대시보드. `main`이 정식 브랜치.
  - **`Obsidian-Vault`**(새 저장소) — 사용자가 로컬 옵시디언 플러그인의 remote를 직접
    여기로 재설정. 이제 이 저장소와 무관.
  - **`House-Hunting`**(새 저장소) — 이 저장소에 `claude/moving-property-dashboard-6lb37e`
    브랜치로 섞여 있던, MtM과 무관한 "집 구하기" 대시보드 스캐폴드를 분리.
- 원칙: **저장소 = 하나의 주제, 브랜치 = 그 주제 안의 버전/작업 갈래.** 옵시디언·

대조해서 발견·수정. 이후 신용(credit) 값도 월별 요약 파일이 아니라 앱의 "신용융자금"
탭 실측치로 전량 교체(최대 30% 오차 확인됨).

**⚠️ 세션이 여러 개 동시에 `main`에 직접 push하면 충돌 위험이 있다.** 특히
`daily.csv`·`collect.py`처럼 여러 세션이 공통으로 건드릴 만한 핵심 파일은 더 그렇다.
권장 방식: 각 세션은 자신의 고유 브랜치에서 작업하고, 안정된 상태가 됐을 때만
main으로 merge한다. main에 push하기 전엔 항상 `git fetch origin main`으로 다른
세션이 먼저 올린 게 없는지 확인하고, 있으면 강제 덮어쓰기 대신 merge할 것.

`data/raw/`에 대용량 원본 파일(xlsx/pdf 등)을 커밋하는 건 저장소 용량을 계속 불릴
수 있으니 주의 — 이미 daily.csv로 가공 완료된 자료라면 `.gitignore` 처리하고
로컬/드라이브 별도 보관을 고려할 것.
