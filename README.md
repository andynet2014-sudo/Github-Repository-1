# 리스크 대시보드 수집기

`260731_리스크관리대시보드_v2.4.5` 의 리스크 엔진을 스프레드시트에서 파이썬으로 옮긴 것.
**지표 정의는 하나도 바꾸지 않았다.** 계산이 일어나는 위치만 바뀌었다.

목적은 하나 — **매일 입력을 0으로 만드는 것.**

```
국장 총평가 = Σ(수량 × 시세) + 예수금
              └ 거래한 날만   └ 자동   └ 거래한 날만
```

## 빠른 시작

```bash
python3 seed_from_xlsx.py v2.4.5.xlsx    # 최초 1회, 시트에서 씨앗 추출
python3 collect.py                        # 이후 매일 (또는 cron)
```

## 파일 역할

사람이 만지는 파일은 두 개뿐이고, 둘 다 **거래한 날에만** 고치면 된다.

| 파일 | 내용 | 갱신 시점 |
|---|---|---|
| `data/positions.csv` | 종목·수량·평단·손절가·섹터 | 매매했을 때 |
| `data/accounts.csv` | 계좌별 예수금·신용잔고 | 매매했을 때 |
| `data/common.csv` | 회사대출·담보비율·연봉 | 바뀌었을 때 |
| `data/rules.csv` | 룰북 임계값 | 기준을 바꿀 때 |

나머지는 스크립트가 쓴다 — `prices.csv`(시세 캐시), `daily.csv`(일별 스냅샷).

## 명령어

| 옵션 | 용도 |
|---|---|
| (없음) | 시세 조회 → 계산 → 기록 |
| `--dry` | 계산만, 저장 안 함 |
| `--no-fetch` | 시세 조회 없이 캐시로 재계산 |
| `--date 2026-08-12` | 특정 날짜로 기록 |
| `--backfill v2.4.5.xlsx` | `01_일별로그` 과거 이력 복원 |

같은 날 여러 번 돌려도 행이 늘지 않고 덮어쓴다.
시세 조회가 실패하면 캐시로 대체하고, **어떤 종목이 왜 실패했는지 출력한다.**

## 검증

`verify_against_sheet.py` 가 계산값을 스프레드시트의 `③ 포지션 ④ 리스크 엔진` 셀과 직접 대조한다.

```bash
python3 verify_against_sheet.py v2.4.5.xlsx
# 26개 지표 대조 — 불일치 0개
```

순자산·Exposure·레버리지·청산여력·담보비율·섹터쏠림·손절 총손실까지 26개 지표가
스프레드시트 값과 일치한다. 정의를 그대로 옮겼다는 근거다.

## 엑셀 스냅샷으로 보기

```bash
python3 export_to_xlsx.py                 # 오늘자
python3 export_to_xlsx.py --date 2026-08-11
```

`snapshot_YYYY-MM-DD.xlsx` 가 생성된다. `collect.py` 와 같은 계산 함수를 그대로 써서
화면 숫자와 항상 일치한다. 시트 2개 — `대시보드`(v2.4.5 00_대시보드 스타일 요약)와
`추이(daily.csv)`(전체 이력 원본). 생성물은 git에 안 올라간다 (`.gitignore`).

## 웹 대시보드

리스크 신호등·계좌·포트폴리오는 이 저장소 데이터로, 매매일지·뷰트래커·생각노트는
v2.4.5 구글시트로 만든 통합 스냅샷 페이지가 따로 있다. 정적 스냅샷이라 자동 갱신되지
않는다 — 최신 내용으로 다시 보고 싶으면 요청하면 된다. 저장소에는 생성 스크립트를
아직 안 넣었다 (요청 시 만들 예정).

## 알아둘 것

**손절가가 평단과 같다.** 9종목 중 8종목의 `stop_price_krw` 가 평단과 완전히 동일하다
(예: SK하이닉스 1887803.429). 지금 R04·R05 가 재는 건 "손절선 하회"가 아니라 **"본전 밑"** 이다.
`data/positions.csv` 에서 고치면 바로 반영된다. 실제 손절가를 넣기 전까지 이 두 신호는
의미가 약하다.

**R07 은 시트에 기준값이 비어 있다.** 그래서 스프레드시트에서는 레버ETF가 순자산의 67%인데도
🟢 준수로 표시된다. 여기서는 잠정 기준 50%를 적용해 🔴 위반으로 잡고, 출력에 `※ 기준값 미설정`
을 붙여 둔다. `data/rules.csv` 의 `threshold` 를 채우면 잠정값 대신 그 값을 쓴다.

**아마존이 반도체/HW 로 분류돼 있다.** 이것 때문에 최대 섹터 비중이 94.5%로 잡힌다.
의도한 분류가 아니라면 `positions.csv` 의 `sector` 를 고치면 된다.

**예수금·신용잔고는 여전히 수기다.** 증권사 API가 없으면 자동화가 어렵다.
다만 거래하지 않으면 변하지 않으니 주 1회로 충분하다.

**과거 이력은 구간을 나눠 담았다.**

| 구간 | 일수 | 쓸 수 있는 것 |
|---|---|---|
| 2026-06-01 ~ 07-29 | 43일 | 국장 총평가·순자산만 |
| 2026-07-30 ~ 08-04 | 3일 | 미장·ISA는 있으나 국장 순자산 없음 |
| 2026-08-10 ~ | 2일 | 전체 순자산·레버리지·청산여력 |

`equity`(전체 순자산)는 세 계좌가 모두 있는 행에만 채웠다. 국장 값만 넣어 "전체 순자산"으로
그리면 6~7월 추이가 실제보다 낮게 나온다. 국장 순자산 흐름(809,140,626 → 271,010,915, 45일)은
연속으로 잡히므로 차트용으로는 충분하다.

## 자동 실행

KRX 마감 후 평일에 돌리려면 (시스템 설정이라 임의로 걸지 않았다):

```bash
crontab -e
```

```
0 16 * * 1-5 cd /path/to/repo && /usr/bin/python3 collect.py >> data/collect.log 2>&1
```

맥이 깨어 있어야 돌고, 처음엔 터미널에 전체 디스크 접근 권한이 필요할 수 있다.

## 시세 출처

- 국내: 네이버 금융 → 실패 시 야후(`.KS` → `.KQ`)
- 해외: 야후 + `USDKRW=X` 환율로 원화 환산

`0193T0`(SK하이닉스X2), `0193W0`(삼성전자X2) 같은 ETN은 제공처에 따라 조회가 안 될 수 있다.
그 경우 캐시 값이 쓰이고 경고가 뜨므로, 뜨면 `data/prices.csv` 를 직접 채워 넣으면 된다.
